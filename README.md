- Зовнішні бібліотеки / Maven / Gradle не потрібні.

## Завдання 1

Для 200 рахунків із випадковими стартовими залишками запускаємо **3000 віртуальних потоків** одночасно. Віртуальні потоки - справжні Java-потоки, доступні починаючи з JDK 21. Кожен переказ захищено двома `ReentrantLock`, які беруться завжди в порядку ID рахунків. Це запобігає циклічному очікуванню (deadlock). Після завершення всіх потоків програма перевіряє сталість загальної суми і невід'ємність кожного залишку.

## Завдання 2

Реалізовано **два власні** обмежені кільцеві буфери (`RingBuffer<T>`) на основі однозв'язного циклічного списку, де `head == tail` означає порожній буфер, а `tail.next == head` - повний (створено `capacity + 1` вузлів). Для очікування використовуються `ReentrantLock`, `notEmpty.await()` і `notFull.await()`. П'ять потоків-демонів записують рядки в перший буфер, два потоки-демони переводять їх у другий, а головний потік **сам** виводить усі 100 повідомлень. Після отримання повідомлень допоміжні потоки коректно зупиняються.

```powershell
mkdir out
javac -encoding UTF-8 -d out src\lab9\*.java test\lab9\*.java
java -cp out lab9.Main
java -cp out lab9.VerificationTests
```

## Важливі зауваження

- Сума переказів задана як `long` у цілих умовних одиницях - немає похибок `double`.
- Кількість успішних/відхилених переказів залежить від реального порядку запуску потоків. Стала тільки сума грошей до та після.
- Для реального дуже великого банку застосовують додаткові перевірки переповнення, журнали транзакцій та надійне відновлення після збоїв.
